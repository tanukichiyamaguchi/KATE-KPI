## 2. 元ワークブックとの差の原因（特定済み）

エンジンとワークブックで「1件・1人」だけずれる項目がありました（来店 552 / 551、来店顧客 359 / 358、有効予約 702 / 701、実績客単価（税込）¥6,188 / ¥6,199、現状LTV ¥9,514 / ¥9,541、6月の予約数 167 / 166、土曜の来店 101 / 100、aoi の獲得顧客 74 / 73、新規顧客セグメント 124 / 123 など）。

原因はすべて同じ1行で、**売上0円の「会計済み」**（2026-06-13・土曜・aoi 担当・HOT PEPPER Beauty 経由・予約金額 ¥5,280／会計 ¥0、この方の来店記録はこの1件のみ）です。ワークブックはこの行を除外し、エンジンは来店として数えています。売上は0円なので売上の合計は一致します。

サンプルには売上0円の会計済みが4件あり、うち3件は**同じお客様・同じ日にキャンセルの記録もある**行でした。
0円の会計を来店に数えるかどうかはオーナーに確認し、**「今のまま来店に数える」**と決まりました（計算は変更していません）。

なお、次の2つはオーナーの判断で定義を変えたもので、ワークブックと値が違うのは意図どおりです。
- 固定化率：分母＝実際に2回来店した方、分子＝そのうち3回目の予約に到達した方（ワークブックは全員に対する3回到達率）
- キャンセル率：HOT PEPPER Beauty 経由の予約を除いて計算（店舗の方針）

### 「目標」タブ

- 「の」で終わる名前（あやの・ゆきの）や「momo(指名)」が、自分の列に一致しなかった → 名前を削らずに照合
- 月を読めない行を黙って捨てていた。とくに、読み込みに使う Google の gviz は **1つの列に日付と文字が混ざると、少ない方の値を空にして返す**（Google の QUERY 関数の説明にある仕様）ため、月が日付に変換された「目標」タブでは「毎月」の行が届かないおそれがある → 行番号つきで警告し、「目標」タブを［書式なしテキスト］にするよう作り方に追記（**この挙動は、この作業環境から Google に接続できないため実際には確かめていません**。警告は、届いた内容だけを見て出すので、どちらの場合でも正しく働きます）
- 「お店」と「合計」の列が両方あると右の列で上書き → 列の順に関係なく「お店」を使い、「合計」は確認用の列として使わない（データタブに「「合計」の列はお店の目標として使っていません」と表示。「合計」はスタッフの目標の足し算であることが多く、お店の目標と違っていても誤りではないため、金額は比べない）。同じ相手の列（「お店」と「お店（税込）」など）の金額が食い違うときは、左の列を使って警告する
- 連携解除・リセットの直後に届いた古い応答で目標が復活／1回の失敗で読み込み済みの目標が消える／予約データが読めないと「読み込み中」のまま → いずれも修正（目標の応答。予約データ本体の応答が遅れて届く場合は、3回目の点検で見つけて修正。下の 3-3）

| 5 | 担当の割合が 99.6% で「100%」、0.4% で「0%」 | — | 0%・100% は本当に 0・1 のときだけ（間は 1〜99%） |

### 「目標」タブ

- 連携を解除して残ったシートのデータが読めていない（サンプルデータを表示中）のに、そのシートの「目標」を読んで、**サンプルの数字の上に本物の目標を出していた** → データを読めたシートからだけ読む。サンプルデータの表示中は目標を出さない
- リセット・連携解除の直後に、読み込み中だった**データ本体の応答**が遅れて届くと、連携が元に戻っていた（main から） → 解除・リセットのたびに世代を進め、古い応答は捨てる
- 予約データ用に保存したURLが会計明細の内容を返すと、「目標」タブが「読み込み中…」のままだった → 読み込む
- 「売上目標」「目標」だけの見出しの列を黙って捨てていた → お店の目標の列として読む
- 読み込みエラーの文言に「。。」が重なり、当てはまらない「共有設定をご確認ください」が出ていた → 原因だけを短く書く

### 画面・アクセシビリティ（数字以外）

- 会計明細だけのデータで「月ごとの数字」の行の見出しが**1文字ずつ縦に並んでいた**（セルの「・直近の月を除く」が列を広げていた） → セルは「※」だけにし、説明は表の下に書く
- **3人の比較表**が 320〜390px で数字が隣とくっつく・切れる → 実際に入りきらないときだけ、4人以上と同じ横スクロールの形にする
- 下のタブバーが、キーボードで移ったフォーカス先を隠す → スクロールで寄せるときの下の余白をタブバーの高さぶん取る
- OSのライト／ダーク切り替えで描き直すと、フォーカス・開いた項目・表の中のスクロール位置が消える → 保つ
- 顧客一覧の並べ替えの見出しが「ボタン」扱いで、列見出し・並べ替えの状態が読み上げられない（中に説明ボタンが入れ子） → 列見出しのまま、中のボタンで並べ替える
- そのほか：説明の吹き出しが iPhone の横向きでノッチにかかる、動きを減らす設定でも切り替えの下地が滑る、横スクロールのスタッフ選択でフォーカスしたボタンが半分隠れる、3人目以降のスタッフの色が予約のたびに入れ替わる、再読み込みでスタッフタブが「比較」のままになる、13ヶ月以上の棒グラフで月の名前が重なる、診断の表の注記が画面外で折り返す、累計グラフ・年商の説明の誤り → いずれも修正

## 4. 計算の前提（データから確かめられないこと）

- **金額は税込で入っている**前提で、税抜表示では10%で割り戻しています（README のとおり）。ポイント・ギフト券を使った会計で「会計時合計金額」がどちらの金額になるかは、サンプルからは確認できません。
- **会計時合計金額に店販（物販）が含まれる**前提で「施術売上＝会計時合計金額−店販金額」としています。サンプルでは店販のある会計11件すべてで会計金額が店販金額を上回っており、前提と矛盾しません。
- **次回予約取得率**は「その来店の後に、予約（今後の受付待ちを含む）か来店がある割合」です。予約を受け付けた日時の列がデータに無いため、「会計時にその場で次回予約を取ったか」と厳密には区別できません。
- **お客様の識別はフリガナ**（無ければ氏名＋電話番号）です。同じ読みの別の方は同一人物として数えます。
- **同じ日に同じお客様の会計が2件ある場合は、来店2回として数えます**（予約が2件あったため。リピート率・ファネル・来店回数に影響）。来店周期だけは別の日の来店どうしで測ります。サンプルには該当がなく、実データでどのくらいあるかは確認できていません。
- **「目標」タブは Google の gviz で読みます**。1つの列に日付と文字が混ざると少ない方の値が空で返る、という挙動は Google の QUERY 関数の説明に基づくもので、この作業環境からは Google に接続できないため実際には確かめていません（警告は届いた内容だけを見て出すので、どちらの場合でも正しく働きます）。

## 5. 実データで確かめる方法

1. ダッシュボードの右上で **「税込」** に切り替えます（サロンボードの金額は税込のため）。
2. 「お店」タブ →「売上・予約」→「月ごとの数字」の **先月の売上・来店** を、サロンボードの同じ月の売上集計（会計済みの合計・件数）と比べます。
3. 合わない場合は、その月の **売上0円の会計** と **キャンセル済みの行** の扱いを確認してください（2. のとおり、0円の会計は来店1件として数えています）。
