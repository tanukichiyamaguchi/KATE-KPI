# KATEstageLASH 蒲田西口店 — KPIダッシュボード

> 予約データを入れるだけで、店舗の状況がひと目でわかる。まつげ・眉毛サロン向けの
> **予約ベースKPIダッシュボード**。完全クライアントサイド・モバイルファースト・
> ダーク/ライトはOSの設定に自動追従。

「予約データ」シート（HOT PEPPER Beauty 等の予約エクスポート形式）を
アップロードするだけで、店舗全体・スタッフ・傾向・RFM顧客分析を、
おしゃれで動的なグラフとして自動生成します。データはすべてブラウザ内で処理され、
どこにも送信されません。

## ✨ 特長

- **入れるだけ** — Googleスプレッドシート連携、またはファイル（`.xlsx` / `.csv`）のドラッグ&ドロップで全指標を自動再計算。
- **2データ統合** — 予約データ（キャンセル・将来予約）＋会計明細（店販・指名）を、フリガナ×来店日で自動結合。突合レポートつき。
- **予約ベースの視点** — 会計済み（実績）＋これからの受付待ち（見込み）を合わせて店舗の“今”を捉える。
- **5つのビュー**
  - **概要** — **売上サマリー（直近3ヶ月/先月/今月の平均月間・平均日間売上）**・定着/リピート・**月次 予約ベース売上**・**月次 予約数の比較（新規/2回目/3回目/4回目以上の内訳・スタッフタブの店舗全体版）**・リテンションファネル・**月次コホート（リピート率／LTV＋顧客LTVを併置）**・**客単価の推移（予約ベース／実績の2本）**・**店販（物販）実績**・来店回数構成
  - **スタッフ** — momo / aoi の**スタッフ比較**（中立の一覧表：来店・直近3ヶ月の月間/日間売上・客単価・リピート率・次回予約率・固定化率・キャンセル率・店販顧客比率）＋ **本人の売上サマリー（直近3ヶ月/先月/今月）** ＋ **自己成長型モチベーション機能**（自己ベスト・育てた常連・次の一手の提案）＋ **自分の推移（自己平均比）** ＋ 月次比較（予約数の**新規/X回目内訳**・売上・客単価・次回予約率・**2回目次回予約取得率**・**月別リピート率・固定化率の推移（獲得月コホート）**・**店販売上**・**施術時間と稼働率**）
  - **傾向** — 曜日別パフォーマンス・月次コホート（リピート率/LTV）・**施術/店販の月次分解**・**時間帯×曜日ヒートマップ**
  - **顧客 RFM** — 9セグメント分類・F×R ヒートマップ・顧客明細（並べ替え可・**呼び戻し対象（周期超過）の絞り込み**）
  - **データ** — アップロード・現在のデータ・計算ロジック ＋ 以下は**管理ロック解除＝オーナーの合言葉を入力した人のみ**
    - **年商** — 既定は**1月1日〜12月31日**の会計済み売上。**年ボタン／全期間／開始・終了日**で任意の期間に絞り込み可（施術売上・店販売上・会計件数・客単価・営業日数・**平均月間売上・平均日間売上**つき）
    - **予約状況（日別カレンダー）** — 過去30日の売上/客数・店販と、**今後1ヶ月の受付待ち予約（件数・予約金額）**を地続きで表示
- **自動更新は30分おき・終日（※ページを開いている端末のみ）** — このダッシュボードは**サーバーを持たない静的サイト**のため、自動更新はブラウザのタイマーで動きます。したがって**誰もページを開いていなければ自動更新は行われません**（次に開いたときに最新を読み込みます）。スプレッドシート連携中は、画面を開いたままの端末で**毎時0分・30分**に再読み込みします。時間帯を決め打ちしないのは、シート側の同期が何時に終わるかをダッシュボードから決められないためです（以前は23時〜翌1時の窓だけを見ていたため、**1:00〜23:00 の22時間はタブを開きっぱなしでも一度も読みに行かず**、深夜2時台に走っていた実際の同期を翌日23時まで取り逃していました）。駆動は長いタイマー1本ではなく**1分おきに実時刻を確認する見張り**なので、端末がスリープしてタイマーが止まっても、復帰した直後に取りこぼしを取り戻します。失敗しても次の30分の回が拾います。実際に動いたかはデータタブの診断（前回の自動更新／次回の予定）で確認できます。管理者画面には**「今すぐ更新」ボタン**もあります。
- **夜間のシート同期が飛んだら、こちらから知らせる** — ダッシュボードは取得できた内容を**そのまま**表示するため、スプレッドシート側の同期が止まると「昨日と同じ数字」が黙って出続けます（取得自体は成功しているので失敗バナーも出ません）。シートの `データ更新日時` が**26時間**より古い場合、**全タブで「スプレッドシートが1日以上更新されていません」**と最終更新時刻つきで知らせます。判定を特定の時刻ではなく経過時間にしているのは、同期が何時に走るかが運用で変わりうるためです（時刻を前提にすると、その時刻から実際の同期までの間、毎晩かならず誤警告が出ます）。
- **シート側の同期を23時台に設定する** — 同期の実行時刻は Google アカウント内の Apps Script トリガーで決まっており、ダッシュボード側からは変更できません。`tools/sync-at-2300.gs` を同期スクリプトのプロジェクトに追加し、`showSyncSchedule`（現状確認）→ `setSyncTo2300`（設定）を1回ずつ実行すると、トリガー設定画面を触らずに毎日23時台へ変更できます。Google の仕様で分は指定できないため実行は23時台のどこかになりますが、ダッシュボードは23時〜翌朝5時を30分おきに読み直すので取りこぼしません。
- **壊れた端末から必ず復旧できる** — 連携URLが「保存されているが読めない」端末でも、**警告バナーと「データ」タブに合言葉の入力欄が出ます**（以前は連携URLが保存されているだけで合言葉カードが消え、URL入力欄は管理ロックの内側にあるため、スタッフ端末からは復旧できませんでした）。端末の保存領域が消えた場合（Safari の自動削除・プライベートブラウズなど）も、**全タブで「この端末は店舗データに接続していません（サンプルデータです）」**と明示します。
- **配信キャッシュ対策** — `index.html` の資産URLには `?v=<package.json の version>` が付きます。GitHub Pages は JS/CSS をキャッシュさせるため、これが無いと**修正をデプロイしても利用者の端末が古い `app.js` を使い続ける**ことがあり、「直したはずの不具合がまだ直っていない」という切り分け不能な状態になります。リリース時は `package.json` の `version` を上げてから `npm run stamp`（`tools/stamp-assets.js`）を実行してください。ずれていれば `npm test`（validate）が失敗します。
- **取得経路を1本に賭けない（反映漏れの防止）** — 通常の編集URLでは、CSVの取得先を**2経路（`/export?format=csv` と `/gviz/tq?tqx=out:csv`）とも並行して取りに行き、中身がいちばん新しいものを採用**します。`/export` は常に現在の内容を返しますが**別オリジンからの取得が遮断される（CORS）ことがあり**、`gviz` は読めますが**Google側で結果がキャッシュされ古い内容が返ることがある**ためです。どちらか一方に賭けると、環境やタイミングによって「シートは更新されているのに反映されない」が起きます。採用しなかった経路の取得結果（データ内の最新日）は、データタブの診断表に**経路ごとに並べて表示**するので、どちらが古いのかがその場で分かります。
- **貼られたURLはそのまま尊重する** — すでにCSVを返すURL（`output=csv` / `format=csv` / `tqx=out:csv`）を貼った場合は、**そのURLをそのまま**使います。タブ名指定（`sheet=`）・範囲指定（`range=`）・`headers=` など、こちらでは組み立て直せない指定を落とさないためです（これらを無視して `gid` から作り直すと、**指定とは別のタブ（1枚目）を黙って読んでしまいます**）。
- **日付表示の主役は「最終読込」** — ヘッダーは `最終読込 M月D日 HH:MM（シート同期 M月D日 HH:MM）` の形です。「最終読込」は**この画面がシートを読みに行って成功した時刻**なので、更新すれば必ず進みます。「シート同期」はシート側が `データ更新日時` 列に記録した同期完了時刻（2枚連携時は古い方）で、**片方のシートの同期が止まるとここは止まったまま**になります。以前は後者を主表示にしていたため、実際には毎回最新を読めていてもヘッダーの日時が動かず「反映されていない」ように見えていました。
- **読み込みに失敗したら黙って隠さない** — スプレッドシートを読み込めなかったときは、全タブ共通の警告バナーで「いま画面に出ているのがサンプルデータなのか、前回読み込んだ内容なのか」を明示します（従来は起動時の自動読み込みが黙って失敗し、サンプルデータが実データだと誤認される恐れがありました）。バナーには**取得先のURLを出しません**（スタッフも見る画面のため、管理ロックが隠しているシートのIDが漏れないよう、経路の種別だけを表示）。読み込みに成功する・連携を解除するとバナーは自動的に消えます。データタブの診断表には失敗の記録を**足す**ので、いま表示されている数字がどのデータなのかは失敗しても分かります。
- **管理ロックは端末に記憶** — 管理用の合言葉の入力は**その端末で最初の1回だけ**。合言葉そのものは保存せず、解除したロック設定の指紋のみを保存するため、端末から合言葉が読み出される心配はありません。合言葉を作り直して差し替えると古い解除は自動的に無効になり、共用端末は「この端末を再ロックする」でその場で戻せます。
- **一流のデザイン** — Apple ライクなエディトリアル。モノクロ＋ブルー1色、余白とタイポ主役、システムフォント（SF Pro / ヒラギノ）、絵文字ゼロ・ライン アイコン。
- **モバイルファースト & レスポンシブ** — 下部ナビ、2カラムのタイル、狭い画面でも横スクロール不要なテーブル、`prefers-reduced-motion` 対応。
- **アクセシブル** — カラーバリアフリー検証済みパレット、キーボード操作、ARIA、ダーク/ライト個別調整。
- **依存ゼロ（実行時）** — Webフォントも外部CDNも不要。手書きのSVGチャート＋システムフォント。Excel読込のみ SheetJS を同梱。

## 🚀 使い方

### 1. そのまま開く
`index.html` をブラウザで開くだけ（同梱のサンプルデータで全機能が動きます）。

### 2. GitHub Pages で公開する
リポジトリの **Settings → Pages** で「Deploy from a branch」を選び、ブランチを `main`（フォルダは `/ (root)`）に設定します。
以後、`main` に push するたびに数分後 `https://<ユーザー名>.github.io/KATE-KPI/` へ自動反映されます。（`.nojekyll` 同梱）

### 3. Googleスプレッドシートと連携する（おすすめ）
スプレッドシートに予約データを入れ、`データ` タブの**「予約データ」欄に URL を貼るだけ**。以後、ページを
開くたびに最新の内容を自動で読み込みます。**「会計明細」欄にも別のシートを貼ると、下記の2データ統合が自動で働きます。**

- 確実な方法：スプレッドシートで `ファイル → 共有 → ウェブに公開 → CSV` を選び、そのURLを貼付。
  ⚠ 公開ダイアログの「**自動的に再公開する**」のチェックが外れていると、公開CSVがその時点で凍結され、
  シートを更新してもダッシュボードに反映されなくなります（チェックを確認するか、編集URLの貼付に切り替え）。
- または、共有を「リンクを知っている全員（閲覧者）」にして編集URLを貼付。
- 1行目の見出しは「予約データ」シートと同じ日本語列にしてください（`data/template.csv` をインポートすると簡単）。
- ⚠ 公開／共有したスプレッドシートはURLを知る人が閲覧できます。個人情報を含む場合は、下記のファイル読込（非公開）をご利用ください。

**同期完了時刻を正確に表示する（推奨）** — 毎日の自動同期（DailyCSVSync 等）が「いつ完了したか」を
ダッシュボードに正確に表示するには、対象スプレッドシートに [`tools/sheet-update-stamp.gs`](tools/sheet-update-stamp.gs) を
一度だけ設定します（手順はファイル冒頭のコメントに記載・約2分）。シートの内容が変わるたびに
「データ更新日時」列が自動で書き込まれ、ダッシュボードのヘッダーと各画面に
「**データ更新 ◯月◯日 ◯◯:◯◯ 時点**」と表示されます。未設定の間は、画面がデータを読み込んだ時刻を
「最終読込」として表示します（同期時刻とは異なる点に注意）。

### 4. 自分のデータファイルで見る
`データ` タブに、**「予約データ」欄と「会計明細」欄の2つのスロット**があります。それぞれに `.xlsx` か
`.csv` をドロップ／選択します（片方だけでも動作します）。列は日本語の見出し名で自動認識するため、
列の並び順は自由です。**文字コードは Shift-JIS / UTF-8 を自動判別**します。誤ったスロットに投入しても、
形式を自動検出して正しいスロットへ振り分けます。

対応する2つの形式：

- **予約データ**（`ステータス` 列つき）— 全指標（キャンセル率・次回予約・RFM ほか）を算出。
  > 主要な認識列：`ステータス` `来店日` `スタッフ名` `予約経路` `フリガナ` `会計時合計金額`
  > `会計時店販` `会計時店販金額` ほか。
- **会計明細**（`会計日`・`区分`・`金額` 列つき、POS/会計エクスポート）— 会計IDごとに1来店へ
  集約し、**店販売上**（`区分＝店販` の `金額` 合計）・客単価・売上・RFM 等を算出。
  ※ 単独では キャンセル情報が含まれないため、キャンセル率は「—（会計実績のみ）」と表示されます。

### 5. 2データを統合する（予約データ＋会計明細）
両方のスロットにデータを入れると、**フリガナ×来店日で自動的に結合**され、予約データ側の
キャンセル率・将来予約と、会計明細側の店販明細・指名・新規再来を**同じ画面**で確認できます。

- 結合はカナ表記と日付の完全一致のみ（あいまい検索はしません）。同一人・同日の複数回来店にも対応。
- 「データ」タブに **突合レポート**（結合率・未突合件数・金額不一致・重複疑い件数）が表示されます。
  例示行のフリガナは先頭1文字のみ表示（マスク）され、個人情報を保護します。
- 結合が1件も成立しない場合は自動的に統合を取りやめ、予約データ単独で表示します。

## 📐 指標の計算ロジック（元KPIワークブック準拠）

| 指標 | 定義 |
|---|---|
| **税抜表示（税込トグル）** | 画面上の金額は既定で**税抜**（元データ＝HOT PEPPER Beauty 等は税込／消費税10%）。ヘッダーの**「税抜／税込」スイッチ**でいつでも切り替え可能（両側ラベルで選択中を明示・選択は端末に保存）。税抜換算はエンジンの金額ソース1か所（正規化時）で行うため、売上・客単価・LTV・店販など全指標が一貫して税抜になる（`compute` の `taxRate` オプション。未指定＝税込のまま） |
| **データ更新日時** | いつ時点のデータかを表す日時。**シート側に記録された同期完了時刻**（後述の `tools/sheet-update-stamp.gs` が書き込む「データ更新日時」列）を最優先で「データ更新 M月D日 HH:MM 時点」と表示。未設定のシートでは、この画面がデータを読み込んだ時刻を「最終読込」として表示（サンプル表示中のみ「基準日」にフォールバック）。複数ソース統合時は古い方＝全データが揃っている時点を採用。内部計算の集計基準日 `asOf` は従来どおり保持し、データタブの詳細カードに集計基準日・データ更新・最終読込を併記 |
| **予約ベース売上** | 会計済みの `会計時合計金額`（実績）＋ 集計基準日より後の受付待ちの `予約時合計金額`（見込み）。**税抜表示** |
| **有効予約** | 会計済み ＋ これからの受付待ち予約（基準日以前の未処理＝滞留は除外） |
| **集計基準日** | 会計済みの最終来店日（アップロード時は自動、サンプルは 2026-07-03） |
| **顧客の識別** | `フリガナ` で名寄せ（なければ 氏名＋電話）。リピート/RFMの母数は来店実績のある顧客 |
| **リピート率（2回到達）** | 分母＝来店実績のある顧客、分子＝2回目の予約（会計済み＋今後の受付待ち予約）を確保した人（**予約ベース**。将来予約も前向きなシグナルとして含む） |
| **固定化率（3回到達）** | 分母＝**実際に2回来店した顧客**（Fvis≥2・オーナー確定）、分子＝そのうち**3回目の予約に到達した顧客**（受付待ちを含み、キャンセルは数えず、キャンセル後に取り直せば数える）。「2回目まで来てくれた方が、その来店で次を取れたか」という接客の成果を測る。月次推移では、分母が育つ前のコホート（月末から**来店周期の中央値**・最低30日が経つまで）と母数5人未満の月は率を表示しない（早く再来した数人だけで100%に見えるのを防ぐため） |
| **リテンションファネル** | 各段の**到達人数は予約ベース**（Fres≥n。受付待ちの予約も到達に数え、キャンセルは数えず、取り直せば数える）。段間の**継続率／離脱率の母数は「実際にその回数まで来店した人」（Fvis≥n）**で、固定化率と同じ考え方（**2回目→3回目の継続率が固定化率と一致**。分母・分子を各段に併記） |
| **成熟ルール（会計明細のみ）** | これからの予約情報が無いデータ（会計明細のみ）でのみ働く保険。初回来店から**45日**経っていないお客様を「成熟母数」から外し、月次コホートの未成熟な月を落とす。**予約データを読み込んでいる場合は自動的に無効**。予約一覧に次回予約もキャンセルも載っているため、「N回目の予約に到達したか」は時間経過で推測せずその場で判定でき、リピート率・固定化率・リテンションファネルにはこのルールを一切適用していない |
| **次回予約取得率** | 来店ごとに、その後の予約が存在した割合 |
| **スタッフの月次客単価** | **予約ベース客単価＝予約ベース売上（実績＋見込み）÷予約数**（元ワークブック準拠） |
| **スタッフの平均（客単価・次回予約率）** | **プール平均（件数で重み付け）＝分子の合計 ÷ 分母の合計**。月ごとの率を単純平均すると来店の少ない月（新任スタッフの当月など）が過大評価されるため、件数で重み付けする。各数値には分母・分子を併記 |
| **総キャンセル率** | **HOT PEPPER Beauty を除いて**算出（店舗全体・スタッフ別とも。サロン都合／お客様都合／無断の内訳つき） |
| **RFM** | R＝最終来店からの日数、F＝**実来店回数**、M＝累計売上。R点/F点から9セグメントに自動分類（閾値は元ワークブックの固定値） |
| **LTV** | 現状＝実績売上÷来店顧客数、予測＝実績客単価×期待来店回数（5回到達までの期待値） |
| **店販（物販）** | 店販顧客比率＝店販を購入した**人数**÷来店した**人数**。店販単価＝店販金額÷店販のあった**会計数**（1人が複数回購入し得るため）。`会計時店販金額`列があれば金額・売上比率も算出（概要／スタッフ別） |
| **2回目次回予約取得率** | 2回目来店時に、次の予約を確保できた割合（スタッフ別の月次推移） |
| **売上サマリー（期間バケット）** | 直近3ヶ月（今月を含まない確定3ヶ月）・先月・今月（集計中）の3区分で、**実績（会計済み）のみ**の平均月間売上と平均日間売上を表示。日間の分母は**営業日**（その期間に1件でも会計があった日数）。月間の分母は「来店のあった月数」（新任スタッフが在籍前の月で平均を下げないため） |
| **自己ベスト** | 確定済み月（当月は除く）の中での、月間来店・月間売上・月間平均単価・**月間店販売上**の自己最高記録。確定月が2ヶ月未満の間は非表示。直近の確定月がそれ以前の全月を**厳密に上回った**場合のみ「自己ベスト更新」を表示（同値は対象外） |
| **平均店販売上/月** | スタッフの月次店販売上の合計 ÷ 実績のある月数（会計時店販金額データがある場合のみ） |
| **育てた常連** | 初回担当した顧客のうち3回以上来店（成熟母数）した人数を、節目（5・10・25…人）への進捗として表示。自分の実績のみで、他スタッフとの比較はしない |
| **次の一手** | リピート率（目安70%）・固定化率（目安60%）のうち、目安との差が最も大きい指標を1件提案。各候補は成熟済みの値・母数20人以上のみが対象。次回予約取得率は目安を設けていないため対象外 |
| **新規/再来ミックス** | 月次の来店を、その顧客にとっての来店回数（新規／2回目／3回目／4回目以上）で分類。基準は来店の実際の順番（`_ord`）で、予約段階の情報には依存しない |
| **月次 予約数の比較（スタッフ別）** | 会計済みの新規/2回目/3回目/4回目以上に加え、受付待ち（見込み）の予約も同じ来店回数（`_ord`）で内訳表示。見込み分は確定分と同色・半透明で重ねて、確定/見込みを視覚的に区別 |
| **施術/店販の月次分解** | `会計時合計金額 − 店販金額` を施術売上とみなし、月次で店販と積み上げ表示。`会計時店販金額`列がある場合のみ算出 |
| **時間帯×曜日ヒートマップ** | 来店時刻（予約データ＝開始時間、会計明細単独＝会計時刻）を9〜20時の範囲にまとめて集計（範囲外は端に寄せる） |
| **スタッフ稼働率** | スタッフ別・月次の施術時間（`所要時間`列の合計）÷ 稼働可能時間（**実際に施術のあった日数 × 1日8時間**）。進行中の当月・未来月は表示しない。予約データのみ算出可能（会計明細には所要時間が無い） |
| **呼び戻し対象（周期超過）** | 最終来店からの経過日数が、本人の来店周期（来店2回以上ある顧客のみ算出可能。1回のみの顧客は店舗全体の中央値で代用）の1.5倍を超えている顧客。顧客RFM明細で絞り込み表示可能 |

計算エンジンは元のExcelワークブック（`店舗全体`/`各スタッフ`/`傾向分析`/`RFM分析`）の

## 🔑 合言葉共有（全端末で同じデータを見る）

CSV/Excelのアップロードはブラウザ内でのみ処理されるため、端末をまたいで共有されません。
全端末で同じデータを見るには**スプレッドシート連携＋合言葉共有**を使います:

1. データをGoogleスプレッドシートに置き、1台の端末でURLを連携する
2. データ入力タブの「全端末に共有（合言葉の設定）」で合言葉を決めて**暗号文**を作る
3. 暗号文で `data/shared-link.json` を置き換えてデプロイする（暗号文はAES-GCM＋
   PBKDF2で保護され、合言葉なしでは復元できないため公開リポジトリに置いても安全）
4. 以後、どの端末でも**合言葉を1回入力するだけ**で店舗データが表示される
   （未連携の端末には概要画面に案内バナーが自動表示される）

合言葉は店名など推測されやすい言葉を避け、スタッフだけに共有してください。
合言葉を変えたいときは手順2〜3を繰り返すだけです（古い暗号文は無効になります）。

### 管理ロック（オーナー用）

データ入力タブには連携中のスプレッドシートURLが表示されるため、**管理用の合言葉**
（店の合言葉とは別）でページの管理操作を保護できます。データ入力タブの
「管理ロック（オーナー用）」で暗号文を作り、`data/owner-lock.json` を置き換えると
有効になります。有効化後は:

- 連携URLの表示・変更・ファイル取り込み・クリアは、管理用の合言葉を入れるまで非表示
- スタッフの初回セットアップ（店の合言葉の入力）とダッシュボードの閲覧はロックの影響なし
- ロック解除はページを開いている間だけ有効（リロードで再ロック・端末に何も保存しない）

## 🔐 プライバシー

アップロードした予約データ（氏名・電話番号などを含む）は**ブラウザ内でのみ**処理され、
サーバーには一切送信されません。同梱のサンプルは、分析上の性質を保ったまま氏名を
疑似名に匿名化しています。
