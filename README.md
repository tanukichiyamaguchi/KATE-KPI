# KATEstageLASH 蒲田西口店 — KPIダッシュボード

> 予約データを入れるだけで、店舗の状況がひと目でわかる。まつげ・眉毛サロン向けの
> **予約ベースKPIダッシュボード**。完全クライアントサイド・モバイルファースト・
> ダーク/ライト対応。

「予約データ」シート（HOT PEPPER Beauty 等の予約エクスポート形式）を
アップロードするだけで、店舗全体・スタッフ・傾向・RFM顧客分析を、
おしゃれで動的なグラフとして自動生成します。データはすべてブラウザ内で処理され、
どこにも送信されません。

## ✨ 特長

- **入れるだけ** — Googleスプレッドシート連携、またはファイル（`.xlsx` / `.csv`）のドラッグ&ドロップで全指標を自動再計算。
- **2データ統合** — 予約データ（キャンセル・将来予約）＋会計明細（店販・指名）を、フリガナ×来店日で自動結合。突合レポートつき。
- **予約ベースの視点** — 会計済み（実績）＋これからの受付待ち（見込み）を合わせて店舗の“今”を捉える。
- **5つのビュー**
  - **概要** — 客単価・リピート/定着・キャンセル・LTV・**店販（物販）実績**・**新規/再来ミックス**・月次推移・来店回数構成
  - **スタッフ** — momo / aoi の**スタッフ比較**（中立の一覧表：来店・売上・客単価・次回予約率・キャンセル率・リピート率・固定化率・店販顧客比率）＋ **自己成長型モチベーション機能**（自己ベスト・累計マイルストーン・育てた常連・次の一手の提案）＋ **自分の推移（自己平均比）** ＋ 月次比較（予約数・売上・客単価・次回予約率・**2回目次回予約取得率**・**店販売上**・育成力・**施術時間と稼働率**）
  - **傾向** — 曜日別パフォーマンス・月次コホート（リピート率/LTV）・人気クーポン・**人気メニューTOP**・**クーポン依存度**・**施術/店販の月次分解**・**時間帯×曜日ヒートマップ**
  - **顧客 RFM** — 9セグメント分類・F×R ヒートマップ・顧客明細（並べ替え可・**呼び戻し対象（周期超過）の絞り込み**）
  - **データ** — アップロード・現在のデータ・計算ロジック
- **一流のデザイン** — Apple ライクなエディトリアル。モノクロ＋ブルー1色、余白とタイポ主役、システムフォント（SF Pro / ヒラギノ）、絵文字ゼロ・ライン アイコン。
- **モバイルファースト & レスポンシブ** — 下部ナビ、2カラムのタイル、横スクロールするテーブル、`prefers-reduced-motion` 対応。
- **アクセシブル** — カラーバリアフリー検証済みパレット、キーボード操作、ARIA、ダーク/ライト個別調整。
- **依存ゼロ（実行時）** — Webフォントも外部CDNも不要。手書きのSVGチャート＋システムフォント。Excel読込のみ SheetJS を同梱。

## 🚀 使い方

### 1. そのまま開く
`index.html` をブラウザで開くだけ（同梱のサンプルデータで全機能が動きます）。

### 2. GitHub Pages で公開する
リポジトリの **Settings → Pages** で「Deploy from a branch」を選び、ブランチを `main`（フォルダは `/ (root)`）に設定します。
以後、`main` に push するたびに数分後 `https://<ユーザー名>.github.io/KATE-KPI/` へ自動反映されます。（`.nojekyll` 同梱）

### 3. Googleスプレッドシートと連携する（おすすめ）
スプレッドシートに予約データを入れ、`データ` タブの**「予約データ」欄に URL を貼るだけ**。以後、ページを
開くたびに最新の内容を自動で読み込みます。**「会計明細」欄にも別のシートを貼ると、下記の2データ統合が自動で働きます。**

- 確実な方法：スプレッドシートで `ファイル → 共有 → ウェブに公開 → CSV` を選び、そのURLを貼付。
- または、共有を「リンクを知っている全員（閲覧者）」にして編集URLを貼付。
- 1行目の見出しは「予約データ」シートと同じ日本語列にしてください（`data/template.csv` をインポートすると簡単）。
- ⚠ 公開／共有したスプレッドシートはURLを知る人が閲覧できます。個人情報を含む場合は、下記のファイル読込（非公開）をご利用ください。

### 4. 自分のデータファイルで見る
`データ` タブに、**「予約データ」欄と「会計明細」欄の2つのスロット**があります。それぞれに `.xlsx` か
`.csv` をドロップ／選択します（片方だけでも動作します）。列は日本語の見出し名で自動認識するため、
列の並び順は自由です。**文字コードは Shift-JIS / UTF-8 を自動判別**します。誤ったスロットに投入しても、
形式を自動検出して正しいスロットへ振り分けます。

対応する2つの形式：

- **予約データ**（`ステータス` 列つき）— 全指標（キャンセル率・次回予約・RFM ほか）を算出。
  > 主要な認識列：`ステータス` `来店日` `スタッフ名` `予約経路` `フリガナ` `会計時合計金額`
  > `会計時店販` `会計時店販金額` ほか。
- **会計明細**（`会計日`・`区分`・`金額` 列つき、POS/会計エクスポート）— 会計IDごとに1来店へ
  集約し、**店販売上**（`区分＝店販` の `金額` 合計）・客単価・売上・RFM 等を算出。
  ※ 単独では キャンセル情報が含まれないため、キャンセル率は「—（会計実績のみ）」と表示されます。

### 5. 2データを統合する（予約データ＋会計明細）
両方のスロットにデータを入れると、**フリガナ×来店日で自動的に結合**され、予約データ側の
キャンセル率・将来予約と、会計明細側の店販明細・指名・新規再来を**同じ画面**で確認できます。

- 結合はカナ表記と日付の完全一致のみ（あいまい検索はしません）。同一人・同日の複数回来店にも対応。
- 「データ」タブに **突合レポート**（結合率・未突合件数・金額不一致・重複疑い件数）が表示されます。
  例示行のフリガナは先頭1文字のみ表示（マスク）され、個人情報を保護します。
- 結合が1件も成立しない場合は自動的に統合を取りやめ、予約データ単独で表示します。

## 📐 指標の計算ロジック（元KPIワークブック準拠）

| 指標 | 定義 |
|---|---|
| **予約ベース売上** | 会計済みの `会計時合計金額`（実績）＋ 集計基準日より後の受付待ちの `予約時合計金額`（見込み） |
| **有効予約** | 会計済み ＋ これからの受付待ち予約（基準日以前の未処理＝滞留は除外） |
| **集計基準日** | 会計済みの最終来店日（アップロード時は自動、サンプルは 2026-07-03） |
| **顧客の識別** | `フリガナ` で名寄せ（なければ 氏名＋電話）。リピート/RFMの母数は来店実績のある顧客 |
| **リピート率 / 定着率** | 来店顧客のうち 2回目 / 3回以上の予約（会計済み＋今後の予約）を確保した割合 |
| **成熟ルール（会計明細のみ）** | これからの予約情報が無いデータでは、初回来店からまだ**45日**経っていない直近のお客様をリピート率・固定化率・ファネル等の母数から一時的に除外（まだ「再来していないだけ」の可能性が高いため） |
| **次回予約取得率** | 来店ごとに、その後の予約が存在した割合 |
| **スタッフの月次客単価** | **予約ベース客単価＝予約ベース売上（実績＋見込み）÷予約数**（元ワークブック準拠） |
| **スタッフの平均（客単価・次回予約率・キャンセル率）** | **月次の単純平均（mean-of-months）**。来店数で重み付けはしない（元ワークブックの各スタッフ集計に一致） |
| **総キャンセル率** | **HOT PEPPER Beauty を除いて**算出（店舗全体・スタッフ別とも。サロン都合／お客様都合／無断の内訳つき） |
| **RFM** | R＝最終来店からの日数、F＝**実来店回数**、M＝累計売上。R点/F点から9セグメントに自動分類（閾値は元ワークブックの固定値） |
| **LTV** | 現状＝実績売上÷来店顧客数、予測＝実績客単価×期待来店回数（5回到達までの期待値） |
| **店販（物販）** | 店販顧客比率＝店販を購入した**人数**÷来店した**人数**。店販単価＝店販金額÷店販のあった**会計数**（1人が複数回購入し得るため）。`会計時店販金額`列があれば金額・売上比率も算出（概要／スタッフ別） |
| **2回目次回予約取得率** | 2回目来店時に、次の予約を確保できた割合（スタッフ別の月次推移） |
| **自己ベスト** | 確定済み月（当月は除く）の中での、月間来店・月間売上・月間平均単価・月間店販成約件数の自己最高記録。確定月が2ヶ月未満の間は非表示。直近の確定月がそれ以前の全月を**厳密に上回った**場合のみ「自己ベスト更新」を表示（同値は対象外） |
| **累計マイルストーン / 育てた常連** | 累計店販成約・育てた常連（初回担当した顧客のうち3回以上来店、成熟母数）を節目（5・10・25…等）に対する進捗として表示。すべて自分の実績のみで、他スタッフとの比較はしない |
| **次の一手** | リピート率・次回予約取得率・2回目次回予約取得率・固定化率のうち、目安との差が最も大きい指標を1件提案。各候補は成熟済みの値・母数20人／件以上のみが対象 |
| **新規/再来ミックス** | 月次の来店を、その顧客にとって初回の来店（新規）かどうかで分類。基準は来店の実際の順番（`_ord`）で、予約段階の情報には依存しない |
| **人気メニュー / クーポン依存度** | 予約データの `メニュー` `クーポン` 列から算出（会計明細単独では取得不可）。次回予約割メニュー比率＝メニュー名に「次回予約」を含む来店の割合。クーポン依存度＝クーポンを利用した来店の割合 |
| **施術/店販の月次分解** | `会計時合計金額 − 店販金額` を施術売上とみなし、月次で店販と積み上げ表示。`会計時店販金額`列がある場合のみ算出 |
| **時間帯×曜日ヒートマップ** | 来店時刻（予約データ＝開始時間、会計明細単独＝会計時刻）を9〜20時の範囲にまとめて集計（範囲外は端に寄せる） |
| **スタッフ稼働率** | スタッフ別・月次の施術時間（`所要時間`列の合計）÷ 営業可能時間（9:00-20:00固定）。予約データのみ算出可能（会計明細には所要時間が無い） |
| **呼び戻し対象（周期超過）** | 最終来店からの経過日数が、本人の来店周期（来店2回以上ある顧客のみ算出可能。1回のみの顧客は店舗全体の中央値で代用）の1.5倍を超えている顧客。顧客RFM明細で絞り込み表示可能 |

計算エンジンは元のExcelワークブック（`店舗全体`/`各スタッフ`/`傾向分析`/`RFM分析`）の
公表値に対して検証済みで、`tests/validate.js` の **69項目すべてに合格**します（売上は1円単位まで一致）。
`tests/kaikei.test.js` は会計明細の成熟トリミング・店販の人数ベース比率・スタッフ平均の mean-of-months 計算・
自己ベスト/累計マイルストーン/育てた常連（Phase 3）・新規再来ミックス/人気メニュー/クーポン依存度/
施術店販分解/時間帯ヒートマップ/スタッフ稼働率/呼び戻し対象判定（Phase 4）を
手計算フィクスチャで回帰検証します。

```bash
npm test   # 回帰テスト一式（validate.js + kaikei.test.js + merge.test.js）
```

## 🔐 プライバシー

アップロードした予約データ（氏名・電話番号などを含む）は**ブラウザ内でのみ**処理され、
サーバーには一切送信されません。同梱のサンプルは、分析上の性質を保ったまま氏名を
疑似名に匿名化しています。

## 🎨 デザイン

デザインは **Apple ライクなエディトリアル**（モノクロ＋ブルー1色・余白主役・システムフォント）で、
店舗ロゴ **KATE stage LASH** のトーンに合わせています。データ色はカラーバリアフリー検証（`dataviz` 基準）に合格したパレットを使用。
